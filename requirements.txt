# requirements.txt — the runtime dependencies, PINNED.
#
# WHY EVERY LINE IS `==` AND NOT `>=`
# -----------------------------------
# This file used to be entirely `>=`. That means the image built on Tuesday and
# the image built on Wednesday can contain different code, from a release nobody
# on this team reviewed, with no change in this repository. Three consequences,
# all of which have bitten real projects:
#
#   * A build that passed CI cannot be reproduced later, so "it worked last
#     week" is unfalsifiable and a bisect is impossible.
#   * A broken or yanked upstream release breaks the DEPLOY, not the PR — it is
#     discovered by a failing rollout rather than by a red check.
#   * Supply-chain compromise of any transitive dependency lands in production
#     automatically. Pinning does not prevent that; it means the version that
#     arrives is one someone chose.
#
# Upgrades are now a pull request that changes a number and runs the suite,
# which is the point. Dependabot (.github/dependabot.yml) opens them weekly.
#
# TRANSITIVE dependencies are deliberately NOT pinned here — this file lists what
# the application imports, which is the readable, reviewable surface. For a fully
# reproducible install (every transitive version, with hashes), generate a lock:
#
#     pip install pip-tools
#     pip-compile --generate-hashes requirements.txt -o requirements.lock
#     pip install --require-hashes -r requirements.lock
#
# The Dockerfile installs this file; switch it to the lock when you want
# byte-identical images across rebuilds.

# ── Identity (accounts, sessions, API keys) ─────────────────────────────
#
# PyJWT signs and verifies the access token (identity/tokens.py). Pinned tightly
# because a JWT library is security-critical: `decode()` gained and changed
# validation defaults across 1.x/2.x, and an unpinned upgrade that relaxes one is
# not a bug we would notice from a passing test suite.
PyJWT==2.10.1
#
# Argon2id password hashing. OPTIONAL AT RUNTIME BY DESIGN — `identity/passwords.py`
# falls back to `hashlib.scrypt` (memory-hard, standard library) when this is
# absent, and upgrades each password to Argon2 on the owner's next successful
# login. Listed here so a real deployment gets the stronger default; the fallback
# exists so a build without a wheel for this platform degrades to strong rather
# than to weak.
argon2-cffi==23.1.0

# ── Relational store ────────────────────────────────────────────────────
# RDS MySQL 8 in production; SQLite (stdlib) when NXR_DATABASE_URL is unset, so
# local dev needs no server. PyMySQL (pure-python, no build step) is therefore
# only needed for a MySQL deploy — the app imports it lazily and runs fine
# without it. It stays in this file because the container image IS the deploy
# artifact and must not have to install it at boot.

# ── Event bus (Redis Streams) ───────────────────────────────────────────
# Best-effort with an automatic in-memory fallback, so this is OPTIONAL for a
# single-process run. It is NOT optional for a deploy: the fallback is
# per-process, so at 2+ tasks each task would see only its own events. Set
# NXR_REQUIRE_REDIS=1 there and the app refuses to start rather than degrade
# silently. Also backs the shared rate-limit buckets (server/ratelimit.py).
redis==5.2.1
