NextXR Digital Twin — Executive Feature Summary

Index Main Feature Sub Feature Description
1 Dashboard & Overview Operations Overview Live overview of the active twin — risk score, total entities, active findings and change-log volume, refreshed continuously from the knowledge graph.
2Machine Twin Dashboard A single live page for any physics twin: health ring, risk score, 3-D scene, streaming telemetry, subsystem condition, findings and the embedded AI co-pilot.
3Active Findings Feed Rolling list of every finding raised against the twin, with severity, originating behaviour rule and detection tier.
4Severity Distribution Breakdown of findings by critical / warning / informational severity for at-a-glance risk posture.
5Entity Breakdown Counts of every governed entity category — physical assets, locations, incidents, processes, documents, actors and mobile assets.
6Platform Status Bar Persistent header showing entity, asset and audit-event counts, the active event-bus backend, and a health indicator that distinguishes healthy, database-offline and server-unreachable states.
7Command Palette Ctrl / Cmd + K spotlight search to jump to any page, open any twin, and toggle dark mode without leaving the keyboard.
8Twin Switcher Header dropdown to change the active twin; every page in the application re-binds to the selected twin instantly.
9 Twin Library & Lifecycle Twin Library Card view of every twin that exists, showing its domain, entity count, creation date and which one is currently active.
10Twin Creation New twins are created and seeded through the platform's single governed write path, so a twin honours validation, audit and event guarantees from the moment it is born.
11Twin Deletion Removes a twin's graph entities and registry record while deliberately preserving its change log as the permanent audit record.
12Domain Templates Fourteen shipped twin templates — HVAC facility, generic facility, nine machine domains, scanned object and blank — each describing exactly what gets seeded.
13Built-in Demonstration Twins Two always-available simulated twins (Helix Data Center, Forge Plant 7) that stream telemetry with no infrastructure required — identical look and behaviour to a live twin.
14Durable Twin Registry Twins persist in a durable registry on a mounted data volume and re-hydrate automatically after a server restart or redeployment.
15 Build a Twin Guided Twin Builder Conversational builder that is the single entry point for creating a twin; it asks only the specifics a chosen domain genuinely needs.
16Domain Selection Eleven one-click domain choices covering turbine, wire-EDM, tram, metro, rolling stock, hospital, EV charging, EV battery, defence base, warship and generic facility.
17Domain-Specific Questions Each domain asks its own grounded questions — engine platform, cell chemistry, campus scale, charge-point count, vessel class — rather than a generic form.
18Natural-Language Understanding Describing an asset in plain English infers the correct domain automatically and starts the questionnaire.
19Live Domain Blueprint As a domain is chosen the builder displays the real components, sensors with units, physics model and injectable fault catalogue it will map from that domain's pack.
20Floor Plan Upload Attach a 2-D floor plan (PNG, JPG or PDF) and the builder reconstructs a full 3-D building twin from it.
21Object Photo Upload Attach a photograph of a physical object and the builder reconstructs it in 3-D and maps it onto the chosen domain's physics.
22Build Progress Log Step-by-step build narration — component mapping, ontology binding, validation, physics wiring and go-live — so the user sees what was actually built.
23Long-Running Build Jobs Reconstruction runs as a background job with status polling, so multi-minute 3-D generation is never lost to a request timeout.
24 3-D Twin Viewer Interactive Building Viewer Architectural-quality 3-D rendering of the twin's building with orbit, pan and zoom, image-based lighting, contact shadows and bloom.
25Wall Display Modes Switch walls between solid, glass and hidden to inspect internal layout and equipment.
26Floor Isolation Isolate any single floor of a multi-storey building to declutter the view.
27Live Severity Colouring Rooms and equipment are colour-coded by live finding severity, so a rule firing lights up the actual physical location in the scene.
28Click-to-Inspect Panel Clicking any asset opens its detail panel: health and condition index, active findings, live physics-computed sensor values, and asset metadata (manufacturer, model, serial, install date, warranty, runtime hours).
29Equipment Gallery The twin's equipment as a catalogue — one 3-D card per asset type, rolled-up worst-case health across instances, opening onto the least-healthy example.
30Reconstructed Model Viewer Twins built from a photograph render their generated 3-D mesh as the twin's own model instead of a stock asset.
31Domain 3-D Scenes Purpose-built live scenes per domain — animated gas-turbine model, wire-EDM machine cell and a full energy-site world for EV charging.
32Scene Persistence Every reconstructed scene is cached per twin on the persistent data volume, so a twin re-renders identically across restarts and redeployments.
33 Live Physics Runtime Continuous Physics Ticker A background runtime advances every live twin's physics roughly once per second and keeps the latest frame available to every read surface.
34Forward Physics Models Each domain ships real engineering models — Brayton cycle, traction power flow, Wells-Riley infection spread, Thevenin battery equivalent circuit, ship stability, radar propagation and more.
35Fault Injection Inject any fault from the domain's catalogue at a chosen severity and watch telemetry, health and findings respond in real time; clear back to healthy at any point.
36Start / Stop Control Pause and resume a twin's live simulation without losing its accumulated state.
37Health Index A physics-derived condition index for the whole asset, computed from the live frame rather than from rule counts.
38Subsystem Condition Per-subsystem health and status — for example compressor, combustor, turbine, rotor and lubrication on a gas turbine.
39Physics Residuals Observed-versus-expected residuals per signal, exposing drift before a threshold is ever crossed.
40What-If Projection Non-destructively project the twin forward under a hypothetical fault or control setting, leaving the live twin untouched.
41 Telemetry & Monitoring Live Telemetry Tiles Every sensor as a live tile with value, engineering unit, status colouring and a rolling sparkline of recent history.
42Signal Heatmap A 60-second anomaly heatmap across all signals, making a developing excursion visible before it becomes a finding.
43Sensor Limits & Status Per-signal redlines classify each reading as normal, warning or critical, in the correct direction for the signal.
44Coupled Dynamics Feed A generative telemetry engine that couples assets through their real graph relationships — producers update before consumers — with a configurable time-acceleration multiplier.
45On-Demand Asset Telemetry Live, physics-computed signals for any individual asset, available on request without a running feed.
46Feed Control Start, stop and monitor the simulated telemetry feed in either scripted or coupled-dynamics mode.
47 Behaviour & Findings Engine Three-Tier Detection Every twin runs three classes of detection side by side: Tier A physics rules, Tier B statistical baselines and Tier C operational rules.
48Monitoring Archetypes Six reusable, data-driven rule kinds — threshold, sustained threshold, rate-of-change, z-score baseline, physics residual and state / heartbeat — so new monitoring needs no new code.
49Governed Finding Persistence Every finding is written through the same validated write path as any other entity, so it is queryable, auditable and appears in topology.
50Incident Escalation Critical findings are surfaced separately as incidents on the dashboard and in the twin's live state.
51Diagnosis Pass A periodic reasoning pass correlates active findings across the twin and records the resulting assessment.
52 Prediction & Forecasting Forward Trajectory Signal-by-signal projection over selectable horizons from one hour to three days, integrated from the twin's own physics model.
53Remaining Useful Life Time-to-limit per component, with the earliest constraint identified as the one that sets the maintenance window.
54Forecast Charts Per-signal trajectory charts with the present value marked, plus a projected health curve.
55Plain-Language Inference A deterministic summary of what is driving the risk, the recommended action and a confidence figure — derived from the forecast, not generated prose.
56Facility Outlook Twins without a physics model still receive a findings-driven forecast with severity and heuristic service windows.
57 Twin Copilot — Assess Diagnosis Agent Assesses component health and out-of-band sensors, identifies the likely root cause and prioritises corrective actions against the domain's compliance regime.
58Analysis Agent Combines the present state with the projected assessment over a chosen horizon, using the twin's own forward physics rather than a language-model guess.
59Cascade Analysis Reasons about whether degradation in one subsystem will propagate into another and how long that takes, rendered as a propagation graph.
60Live Narration A running plain-language commentary on what the twin is currently doing, refreshed on a deliberately slow cadence matched to how fast the physics actually moves.
61Predictive Alert Raises a warning only when an operating limit is genuinely projected to be crossed, and stays silent otherwise.
62AI Provenance Badge Every agent answer is labelled with its source — real model reasoning, deterministic fallback, or nothing-to-report — together with the model used and token consumption, so a fallback can never be mistaken for a real assessment.
63 Twin Copilot — Act Work Order Generation Produces a compliant maintenance work order from the current diagnosis: ordered steps, acceptance criteria, safety warnings, required parts and sign-off authority.
64Parts Procurement Converts the work order into part numbers, quantities, unit costs, lead times and sources.
65Incident Reporting Generates a formal incident report with classification, symptoms, physics evidence, probable cause, regulatory closure references and return-to-service criteria.
66 Twin Copilot — Train & Ask Repair Procedure Trainer Builds the correctly-ordered repair procedure for a selected fault, where each step states what goes wrong if it is skipped and what goes wrong if it is done out of order; steps are ticked off to enforce sequencing.
67Dashboard Copilot Chat Conversational question-and-answer grounded in the twin's current telemetry and findings, available both on the dashboard and in the copilot console.
68AI Mechanic Multi-turn troubleshooting that asks the technician diagnostic questions back and tracks a working hypothesis across the conversation.
69Horizon Selection Assessment and action agents can be run against any horizon from one hour to one week.
70Snapshot Mode Every agent can be run either against a live twin or against caller-supplied telemetry, with the response declaring which source was used.
71 AI Maintenance Director Guided Repair Takeover A full-screen, cinematic mode in which the assistant takes control of the twin, flies the camera to the fault and walks the repair through to completion.
72Component Highlighting The failing subsystem is isolated and highlighted in the 3-D scene as the explanation proceeds.
73Method Panels Step-by-step repair method presented alongside the machine, with live telemetry visibly recovering as each step is completed.
74Domain Repair Plans Ships repair plans for turbine, wire-EDM, EV energy site, hospital, data-centre and manufacturing domains.
75 Domain Packs Gas Turbine Engine Exhaust gas temperature, dual shaft speeds, fuel flow, vibration, pressure ratio and oil signals across five subsystems, with health and remaining-useful-life.
76Wire EDM Machine Eighteen discharge, dielectric, wire-transport and axis signals across four subsystems, including wire-break risk and surface finish.
77Metro Rail Network A whole MRT network — lines, stations, platforms, permanent way, third-rail traction power, signalling and station services — with on-time performance, headway and passenger load.
78Rolling Stock A single train set at vehicle level: traction, bogies, braking, doors and auxiliaries with health and remaining-useful-life.
79Tram / Light-Rail Network A complete tram network with rolling stock, overhead-line traction power, substations, track and points, signalling and service operations, including live per-vehicle positions.
80Hospital Campus Theatres, ICU, emergency, pharmacy, wards, medical gas, water safety, power resilience, sterilisation, infection control and patient flow as one governed twin.
81EV Charging Network Stations, chargers, grid connection, transformer ageing, on-site solar and vehicle-to-grid export with live tariff and revenue.
82EV Battery Pack Cell-level modelling with equivalent-circuit electrical behaviour, thermal coupling and degradation, monitoring imbalance, state-of-health and thermal-runaway risk.
83Military Base (C4ISR) Perimeter, command centre, radar, hangars, runways, fuel and ammunition storage and NBC monitoring with mission readiness and force protection.
84Warship Naval surface combatant with gas-turbine propulsion, stability under progressive flooding and hull structural fatigue.
85Facility Packs HVAC, common-facilities, data-centre and BIM packs supply the building substrate — eighty-plus entity classes across eleven building systems — used by the plan-reconstruction path.
86 Domain Operations Views Live Network Map Geographic live map for metro and tram networks showing line status, station condition and per-vehicle position.
87Depot Board Fleet availability board with predicted vehicle readiness by depot.
88Clinical Views Five hospital-specific views: bed board, operating-theatre calendar, patient-flow funnel, infection-risk map and medical-gas schematic.
89Energy Views Four EV-specific views: charging geographic map, grid load curve, vehicle-to-grid trading view and cell-level battery heatmap with solar simulation.
90Defence Views Three defence-specific views: NATO APP-6 tactical map, mission readiness board and warship damage-control diagram.
91Manufacturing & Data-Centre Views Rack-level and production-line scenes with cooling, power and OEE telemetry for the built-in demonstration twins.
92 Plan-to-3D Reconstruction Floor Plan Interpretation A vision model reads an uploaded 2-D plan and extracts rooms, walls and equipment.
93Building Geometry Generation Extracted rooms and walls become a metric 3-D scene graph with correct storey heights and multi-floor support.
94Room Classification Rooms are classified by function so the right equipment, services and monitoring are applied.
95Equipment Classification Every detected item is mapped to a canonical ontology class and a 3-D viewer asset, separating monitored equipment from decorative fit-out.
96Automatic Furnishing Rooms are furnished automatically from a shared 3-D catalogue so a reconstructed building reads as a real space.
97Service Auto-Wiring Power, HVAC, water, fire and network services are generated and connected to the rooms they serve, producing a coupled twin rather than a static model.
98Hospital Campus Generator A purpose-built two-storey hospital generator laying out real clinical wings — emergency, imaging, surgical suite, sterile supply, pharmacy, blood bank, ICU, wards and isolation — with sector tagging and plausible asset metadata.
99Resilient Fallback Model If a plan cannot be parsed, a plausible building of the right facility type is synthesised so the twin always renders.
100 Object Reconstruction Photograph to 3-D Model A single photograph of an object is reconstructed into a textured 3-D mesh using a hosted generative reconstruction service.
101Multi-Stage Pipeline Understand, segment, prior retrieval, reconstruct, mesh repair, refine, enhance, validate and export run as discrete inspectable stages.
102Geometry Prior Library A curated library of reference geometries improves reconstruction fidelity for known asset types.
103Job Store & Artifacts Every reconstruction is a tracked job with per-stage status and downloadable artifacts, including the final model file.
104Scan-to-Twin Mapping A scanned object can be bound to a domain so the generated mesh becomes the visual body of a fully live physics twin.
105 Ontology & Governance Ontology Schema Service Machine-readable access to the platform ontology — version, classes, taxonomy categories, predicates, per-class properties and behaviours.
106Validation Gate Every mutation is validated against SHACL shapes before it can touch the graph; invalid data is rejected outright with no partial write and no audit entry.
107Single Write Path All writers — user interface, agents, behaviours and the telemetry feed — go through one governed writer that validates, commits, records the change and publishes the event.
108Archetype & Asset Catalogue A published catalogue of behaviour archetypes and asset types available for binding to any twin.
109Ontology Defaults Ontology obligations such as what a sensor observes are injected automatically, so no caller has to encode ontology knowledge.
110Self-Contained Domain Packs Each vertical is one folder containing its ontology, shapes, physics, behaviours and prediction, so a new domain is added without touching the platform core.
111 Change Log & Audit Tamper-Evident Ledger Every committed mutation is recorded in a SHA-256 hash-chained ledger; altering any historical entry invalidates every hash after it.
112Change Log Viewer Live audit view of every create, update and delete with actor, entity and timestamp.
113Per-Entity History The full change history of any individual entity, including field-level before-and-after values.
114Audit Retention Deleting a twin never deletes its audit chain — the record of what happened survives the thing it happened to.
115 Graph Data Services Entity Queries Tenant-scoped listing and retrieval of entities by category, with relationships resolved.
116Findings Queries Query findings across the twin or for a specific asset, with severity filtering.
117Topology Graph The twin's infrastructure nodes and edges with finding counts aggregated onto the entities they flag.
118Key Metrics Entity counts, finding severity distribution and audit-event totals as a single metrics call.
119Write Services Create, update, delete and relate entities through the governed write path, with validation applied to every call.
120Graceful Degradation When the database is unreachable, read services return valid empty results flagged as degraded rather than failing, so the application stays usable and honest about its state.
121 Event Bus & Real-Time Per-Tenant Event Streams Each twin gets its own event stream, so a consumer reading one twin's events can never observe another's.
122Live Event Subscription Browser clients subscribe to a twin's committed mutations over a server-sent event stream and update in real time.
123Bus Telemetry Published, failed and dropped event counts with recent-event inspection for operational visibility.
124Non-Blocking Delivery Event publication is best-effort and never affects the write that produced it; a message-broker outage degrades live fan-out only.
125 Security & Multi-Tenancy API Key Authentication Every request is authenticated by API key, configured through environment settings rather than stored in code.
126Role-Based Access Keys carry an administrator, write or read-only role that governs what operations they may perform.
127Tenant Isolation A key scoped to one tenant cannot read or write another tenant's data; every write path is tenant-scoped by construction.
128Public Health Endpoints Health and readiness checks are reachable without credentials so platform monitoring works without privileged keys.
129 Integration & Embedding Embeddable Application The twin application runs both standalone and embedded inside a host portal as a federated remote module, sharing routing with the host.
130Isolated Mounting The embedded view mounts under its own rendering root, guaranteeing that 3-D content behaves identically inside a host application and standalone.
131Twin Snapshot Service A single call returns a twin's metadata together with its latest telemetry, findings and health — the integration surface a host portal polls.
132Prediction Service Forecast and remaining-useful-life for any twin exposed as a standalone service call for external consumers.
133AR Overlay Service Versioned augmented-reality maintenance steps for any asset, grounded in its type and its live findings.
134 Deployment & Operations Single-Container Deployment The application and all platform services build into one container image serving both the interface and the API from a single address.
135Local Development Stack A one-command local stack brings up the database, message broker and platform services together.
136Persistent Data Volume Twin registry, audit ledger and reconstructed scenes are written to a mounted volume so nothing is lost on redeployment.
137Platform Health A health service reports database connectivity, event-bus backend and overall platform status.
138Degraded-Mode Operation With the database offline the interface still loads, twins still list and the user is told precisely what is unavailable and why.
139 Pack Marketplace Domain Pack Catalogue Catalogue of installed and available domain packs and capability modules. Presentation layer only at this version — runtime install and unload of packs is not yet wired to the pack loader.
Note. Index 139 (Pack Marketplace) is the only entry in this catalogue that is not fully wired end to end; every other feature listed is implemented in the current codebase. The platform ships ten live machine-twin domains and four ontology / functional building packs, fourteen shipped twin templates, fourteen embedded AI agents, and two always-on demonstration twins that require no infrastructure.
