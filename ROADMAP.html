June BIM Sprint — Plan → 3D Building

One vertical, four weeks, one shippable feature a week. Drop a building plan — a floor-plan image, a PDF, later an IFC model — and watch the platform reconstruct it into a living, interactive 3D twin, with live alerts painted onto the actual rooms and equipment.

Sprint window: 23 Jun → 18 Jul 2026 · Input: 2D images/PDF first, IFC fast-follow · Compiled from the platform audit, June 2026

Why this vertical, why now

The platform already owns the front half of a plan→3D pipeline — the upload endpoint, the Vision Agent, the spatial ontology, the validated write path. But the tail is stubbed, and there is no way to get a plan in from the UI. The BIM sprint takes the existing pipeline's two weakest ends — understanding a plan and rendering a building — and turns them into the product's centerpiece. Everything in the middle (Schema Mapper → Validator → Graph Writer) is reused unchanged.

The four weeks

Week 1 “Drop a Plan” ingestion + BIM Studio 23–29 Jun

Close the missing front door. Give the platform a real upload surface — the entry point the whole vertical hangs off.

Frontend

  • New panel BIM Studio with a drag-and-drop + file-picker drop zone; registered under a new BIM section in the sidebar.
  • A compact drop zone added to Build a Twin so a plan can be dropped mid-conversation.
  • Accept PNG/JPG and PDF (render page 1 to an image with pdfjs-dist); pass .ifc/.dxf straight through for the fast-follow.
  • Wire to the existing twinAgentUploadData() client method — no new plumbing.

Backend

  • Tiny change to twin_upload: tag each file's type from its extension (image vs bim) so Week 2's parser can branch.

Ship Drag a floor plan onto BIM Studio → it attaches to a live twin session and previews on screen.
Week 2 Plan Parser agent + BIM geometry ontology 30 Jun–6 Jul

Turn a plan into a validated graph of the building with real geometry — not just a count of boxes.

Agents

  • Upgrade the Vision Agent into a Plan Parser: emit a format-agnostic bim_model JSON — building outline, levels, rooms (polygon/bbox + area), walls, doors/windows, and placed equipment (label, type, room, x/y).
  • Upgrade the Schema Mapper to draft Building → Floor → Room/Zone → equipment carrying geometry, linked via containedIn / contains / locatedAt.

Ontology — new BIM pack (Layer 4, extends CFP downward; respects the freeze rule)

  • Geometry datatype properties: footprint (WKT/GeoJSON), originX/Y/Z, widthM, lengthM, rotationDeg, levelIndex.
  • A bim:BuildingPlan Document subtype that retains the source plan for provenance.
  • Registered so the new types resolve in the SHACL write gate — commits flow through the unchanged Validator → Graph Writer path.
New: packs/bim/bim-classes.ttl, packs/bim/bim-shapes.ttl · Edit: agents/twin_agents.py (vision_agent, schema_mapper), pack registry
Ship Dropping a plan commits a real Building→Floor→Room graph with geometry, SHACL-validated through the existing write path.
Week 3 Real 3D Scene Generator (replace the stub) 7–13 Jul

Turn the committed building graph into renderable 3D geometry.

Backend

  • Rewrite scene_generator to read Building/Floor/Room + equipment and emit a glTF-compatible scene-graph JSON: extruded floor slabs (area/footprint + elevation), walls from polygons/segments, room volumes, and equipment meshes at their coordinates.
  • A per-entity color slot, keyed by entity id, so Week 4 can paint live status onto it.
  • Procedural fallback (grid / force-directed placement) when geometry is missing — so non-BIM twins still render something.
  • Returned via the existing /agents/twin/scene endpoint — no new route.
Edit: agents/twin_agents.py (scene_generator) · Reuse: server/agent_routes.py (twin_request_scene)
Ship /agents/twin/scene returns a full 3D scene reconstructed from the building graph — levels, walls, rooms, equipment.
Week 4 Interactive 3D viewer + live findings overlay 14–18 Jul

The payoff — walk through your reconstructed building in 3D, with live alerts on the real rooms and equipment.

Frontend

  • Build the viewer inside BIM Studio with three + @react-three/fiber + @react-three/drei: orbit / pan / zoom, floor isolation & explode, click an asset → properties + findings drawer.
  • Color-code rooms and equipment by finding severity (green / amber / red) from /findings + the live event stream — a Tier-C finding lights up the actual room in 3D.
  • Stretch: animate flow along nxr:feeds / cfp:suppliesAirTo edges.

IFC fast-follow

True BIM, no downstream rework

The Plan Parser emits a format-agnostic bim_model schema. An IFC track — an ifc_parser.py using IfcOpenShell (optional dependency, stub-safe when absent) — produces the same schema directly from a .ifc model's native 3D geometry. Because everything from the Schema Mapper onward consumes bim_model, IFC slots in straight after Week 2 with zero changes to the ontology, scene generator, or viewer. Highest fidelity, deferred until the image path proves the full loop.

Definition of done

The one demo that proves the sprint

An operator drags an architectural floor plan onto BIM Studio. Within seconds the platform parses it, commits a validated Building→Floor→Room graph with geometry, and renders an interactive 3D model of the building. The feed runs; a Tier-C rule fires a finding; the affected room turns red in the 3D view. Click it — properties, findings, and the diagnosis are right there. Drop a plan, get a living building.
